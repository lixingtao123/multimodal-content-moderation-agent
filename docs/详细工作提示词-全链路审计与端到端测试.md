# 详细工作提示词 · 全链路审计与端到端测试（R21）

> 用途：本提示词是「内容风控智能治理系统」R21 全链路审计的执行蓝图。
> 目标：①复盘全部功能点与改动点形成文档；②以前端页面为入口整理端到端测试用例；
> ③技术实验室匹配当前项目逻辑；④全功能接入日志可分析；⑤真实执行全链路测试并核对。
>
> 使用方式：将本提示词作为执行纲领自调用——按【工作阶段】推进，每一阶段产出可交付物，
> 全部完成后按【完成判据】逐项核对。禁止 mock、禁止伪造验证、禁止跳过。

---

## 【角色】

内容风控系统全链路审计工程师 + 前端 E2E 测试设计者 + 可观测性审查专家。
职责不是"让代码跑起来"，而是**证明每个功能点真实可用、可观测、可复现**。
发现断链/缺日志/逻辑与页面不符，立即修复并回归。

## 【硬约束】

1. **禁止 mock/伪造/模拟功能**：凡标注"已实现"的功能，必须真实输入→真实输出→真实日志三重验证。
   mock 仅允许在单测隔离外部依赖（LLM API / Redis / DB）；集成与端到端必须走真实链路。
2. **禁止跳过**：无法验证的功能显式标注「待验证/依赖X/未实现」，不得混入"已实现"。
3. **日志为准**：多智能体/链路的验证以真实 logs 为准，不得用"代码看起来对"代替。
4. **页面与实现一致**：前端页面展示的逻辑必须与后端实现匹配（重点技术实验室）。

## 【工作阶段】

### 阶段 0：全量探索
并行探索三路：①前端页面/功能块/调用的接口；②后端全部端点 + 日志埋点覆盖度；③技术实验室实现与当前逻辑差异。
产出：接口全貌清单 + 埋点缺口清单 + 技术实验室差异清单。

### 阶段 1：产出文档
1. **《功能与改动复盘文档》**：系统架构图 → 功能模块清单（前端页面×后端接口）→ 历次改动点（R0-R20，含 E/D/L/G/T/M/Q 组）→ 当前状态与已知问题。
2. **《前端端到端测试用例文档》**：以每个前端功能为入口，逐条列出：页面 → 操作路径（点击序列）→ 调用的 HTTP 接口 → 请求体/测试输入 → 期望结果 → 日志核验点。覆盖 13 页面全部功能块。
3. **《详细工作提示词》**（本文档）：完成并自调用。

### 阶段 2：代码更新
1. **技术实验室匹配当前逻辑**：
   - 全流程可视化：更新 `/tech/pipeline-flow` 返回的管线拓扑为当前三车道架构（triage→lane→各节点→termination）；前端渲染适配。
   - RAG / MCP / Skills：核对数据源真实性与当前实现一致，差异即修。
2. **全功能日志埋点补全**：
   - 补三车道节点埋点：triage_node / fast_lane_node / brain_node / 终止双签检查。
   - 核对所有审核链路（同步/异步/多模态/HITL）均走 start_pipeline。
   - 核对所有 API 端点有日志痕迹；缺的补（原则：每个请求可归因、可复现）。

### 阶段 3：全链路测试执行
按《前端端到端测试用例文档》逐条真实执行（直接调用后端 API 模拟前端操作）：
- 每页功能：构造测试输入 → 调用接口 → 断言响应 → 核验 pipeline.jsonl 日志链路 → 记录结果。
- 重点链路：三车道（low 快车道 qwen / med 标准 / high brain）、HITL、异步任务、RAG、评测。
- 发现 bug 立即修复并回归。

### 阶段 4：工作核对
逐项核对用户需求 vs 交付物：
| 用户需求 | 交付物 | 验证 |
|---|---|---|
| 复盘功能点与改动点 | 复盘文档 | 文档含架构+功能+改动+状态 |
| 前端页面为入口的 E2E 用例 | E2E 用例文档 | 13 页面全覆盖 |
| 技术实验室匹配当前逻辑 | 代码更新 + 验证 | 接口返回与页面渲染一致 |
| 全功能接入日志可分析 | 埋点补全 + 验证 | 每个链路有 pipeline 日志 |
| 提示词自调用 | 本文档 | 按阶段执行完成 |
| 执行计划 | Todo + 阶段执行 | 逐项完成 |

## 【分层测试】

| 层级 | 范围 | 执行 |
|---|---|---|
| L0 静态 | ruff(E9/F821) + tsc | 每轮改动后 |
| L1 单元 | pytest 全量 | 回归不降 |
| L2 集成 | 工作流/跨组件 | 重点链路 |
| L3 端到端 | 前端操作模拟 → API → 链路 → DB → 日志 | 按 E2E 用例 |

## 【验证方法模板】

对每个功能点：
1. **入口**：前端页面/操作（或等价 API 调用）
2. **接口**：HTTP 方法 + 路径 + 请求体
3. **测试输入**：具体数据
4. **期望输出**：响应字段 + 决策
5. **日志核验**：pipeline.jsonl / backend.log 中该 content_id 的节点链路
6. **结论**：✅ 真实可用 / ⚠️ 待验证 / ❌ 有 bug（修复后回归）
