## 0. 用一个比喻开场

现在的系统 = **一个只有"全科医生"的诊所**：不管感冒还是疑难杂症都挂同一个号、排同一队、花同样的时间。诊所里其实还有"专家会诊、复查、请上级审批"，但请上级审批的电话线**是断的**；专家会诊和复查虽然能工作，但只干"走过场"的活（见 §1.4）。

改造后 = **门口加分诊台**，快速把脉分出三档：感冒去药房（本地小模型）、普通病看全科（现状不变）、疑难杂症上专家会诊（指挥官拆计划、多医生并行、真辩论）。

### 1.2 多模态真实流程（"双轨"，不是纯"转文本"）

代码确认（`planner_node` v4.0，5-Phase）：

```
多模态请求 → planner_node
   │
   ▼
Phase1 文件解析    FileAgent 拆文件，提取文本+嵌入图片
   │
   ▼
Phase2 并行独立分析 图片 → ImageAgent(VL大模型)：OCR + 场景描述 + 违规判断 + 风险分
  (Semaphore 5)    音频 → AudioAgent(ASR转写 + 违规判断)
                    ★ 每个模态此时已产出自己的独立判断
   │
   ▼
Phase3 转文本融合   原文 + OCR文字 + 图片视觉描述 + ASR转写
                   → 合并成一段 fused_text
                   → 交给 TextAgent(纯文本模型)做"图文融合"综合判断
   │
   ▼
Phase4 跨模态关联   规则引擎(0 LLM)：图文矛盾 / 图文互证 / OCR融合 / 音频关联
   │
   ▼
Phase5 输出         最高风险图片→image_result，融合文本→text_result
```

**精确理解**：①各模态先被各自模型独立分析（带自己的违规判断）→ ②所有分析结果降维成一段文本，交给文本模型做综合判断 → ③规则引擎做跨模态关联。

**已知短板**：终判时**文本模型结果是主角**。图片说"有违规"、文本说"没有"时，规则只记录一条 suggestion（"建议以图片为准"），**视觉/语音的独立判断没有真正参与融合决策**——"文本中心"架构的固有弱点。

### 1.3 react 两步 + risk 内联辩论（代码确认）

**react_agent 是两步**（`react_agent.py` v2.0）：

```
触发：有违规 且 (置信度<0.6 或 对抗样本) 且 未强化过
   │
   ▼
Phase1 主动搜索 (ReAct)     Thought→Action→Observation 循环，最多5步
                          工具：keyword_check / history_search / deep_analysis
                               image_hash / rag_retrieve / account_check
                               escalate / finalize
   │
   ▼
Phase2 保守校准 (原Reflexion合并)  ReflexionEvaluator 评估4项：
                           ①置信度达标？ ②有历史案例？ ③风险分匹配？ ④对抗信号？
                           不通过→不重新搜索，只调数字：
                           confidence×0.85、对抗时risk×1.2
   │
   ▼
   结果合并进 text_result（react_enhanced 标记）
```

**它不含辩论**：单 agent 自我循环（自己思考→自己调工具→自己观察→自己终判），没有第二个视角对冲。Phase2 是降级版反思（只调数字，不重做）。

**risk_agent 内含"单轮投票式辩论"**（`risk_agent_node` v4.1）：

```
risk_agent_node（3阶段）
   │
   ▼
阶段1 意见收集+协商（原 Debate 内联）
   panel.collect_opinions(state) 从各模态结果提取意见{agent,类型,置信度,专业度}
   │
   ├─ ≥2意见且类型冲突 → panel.debate() 单轮投票
   │     自动选模式：有专业agent→加权投票(专业度×严重度×置信度)
   │                无→多数投票；分歧小→共识；争议大→升级人工
   ├─ 类型一致 → 快速共识（平均置信度）
   ├─ 仅1个意见 → 直接采纳；Agent不确定 → 标记需人工
   │
   ▼
   辩论升级或需人工 → 设置 _human_review 并 return（暂停等人工）
   │
   ▼
阶段2 风险计算：GraphRAG洞察 + risk_agent.process → PASS/REVIEW/REJECT
   │
   ▼
阶段3 事后处理：反馈收集/硬样本挖掘/记忆整合（fire-and-forget）
```

**它的"辩论"是什么（真话）**：

| 维度 | 真相 |
|---|---|
| 模式 | **单轮加权投票**（统计汇总），不是多轮互相反驳 |
| 论据 | opinion 只有 {agent,类型,置信度}，**无证据链** |
| 权重 | expertise_weight 是**固定表**，不随历史准确率更新 |
| 升级 | 争议大直接跳人工，不尝试二轮协商 |

### 1.4 现状的三个问题（精确版）

1. **没有快车道**：一句话的"你好"和一篇政治长文花同样的成本、同样的时间。
2. **深度机制全部"走过场"**：
   - 辩论：不是真辩论，是单轮投票，无证据链、权重固定（§1.3）。
   - 反思：只调置信度数字，不回头重做（§1.3 Phase2）。
   - **人工审核彻底断线**：`human_in_loop` 节点在编译图里但**无任何入边，永不触发**——risk_agent 判"需人工"也只写个标记，没人真被叫来。
3. **工具一次性全摆**：8 个工具全量暴露，上百个时模型眼花、选择准确率崩、上下文挤爆。

| 步骤 | 名字 | 做什么 | 新增/保留 | 花钱吗 |
|---|---|---|---|---|
| ① | 安全门 InputGuard | 拦注入、清洗脏数据 | 已有 | 不花 |
| ② | 分诊台 | 小模型输出风险×复杂度，规则兜底，保守校准 | **新增** | 本地，便宜 |
| ③ | 快车道 | 小模型粗判 + 语义缓存；犹豫/高危即升级 | **新增** | 本地，几乎免费 |

| ⑥ | 指挥官 编排Agent | 复用 TaskPlanner 拆计划，输出结构化 plan | **新增** | 大模型一次 |

### 2.5 关键设计判断：不是所有 agent 都 ReAct，工具调用分层（★回答你的问题）

**"动态调用工具"是全局的，但"ReAct 多步推理"是局部的**。工具调用 = 统一基础设施（所有 agent 走 skill_router）；ReAct = 只有少数深挖 agent 需要。

| Agent 类型 | 推理模式 | 工具怎么用 | 现状/新增 |
|---|---|---|---|
| 快路径 tier=low | 0 推理（规则+小模型） | 基本不用工具 | 新增 |
| 模态审核 agent（标准路径） | **单次 LLM 推理** | 按需 0-1 次，走统一路由层 | 现状保留 |
| ReAct 深挖 agent | 多步 ReAct 循环 | 多步动态调用 | 现状保留 |
| 编排 Agent（深度路径） | **Plan-and-Execute**（先规划后执行） | 规划时选工具集（Select 步） | 新增 |
| Worker（深度路径） | **单步执行** | 用编排器选好的工具 | 新增 |

**为什么不该全上 ReAct**：
1. **成本**：ReAct 每步一次 LLM 调用，5 步=5 次。大多数审核是判别式任务（敏感词命中即违规），不需要多步求解。
2. **可调试性**：全 agent 套循环 → 嵌套循环互相套娃，失败无法定位。
3. **分层语义清晰**：谁做规划（编排 Agent）、谁做执行（worker 单步）、谁做深挖（ReAct）职责分明。

**大厂对标**：OpenAI function calling = 按需 0-1 次工具；Anthropic multi-agent = 只有 orchestrator 规划，worker 单步执行；Coze = 只有特定节点配循环。

## 4. 每个改动带来什么效果

| 改动点 | 一句话效果 | 量化指标（⚠️待实测） |
|---|---|---|
| D1 指挥官 | 复杂任务任务级分解，能并行、能重规划 | 多轮任务完成率↑ |
| D2 分诊台 | 简单请求不再花大模型钱，高危不放走 | 快车道延迟<500ms，成本↓ |
| D3 技能路由 | 上百工具也选得准，上下文不挤爆 | 工具选择 Hit@3 ≥0.85 |
| D4 工具可靠性 | 非法参数被拦住，工具挂了不死 | 工具成功率 ≥95% |
| D5 工具质量分 | 不好用的工具自动被弃用 | 质量分覆盖 100% |
| D6 模型级联 | 便宜的先上，贵的兜底 | 升级率 + 成本↓ + F1 差距<2pp |
| D7 语义缓存 | 查过的意思一样的直接复用 | API 调用↓ |
| D8 可观测性 | 误判能定位到具体哪一步 | 归因覆盖率 |
| D10 修断线+升级 | 真辩论（证据化多轮）+ 真反思 + 人工真可触发 | 争议样本准确率↑ |
| D11 融合升级 | 多模态不再"文本一家说了算" | 图文矛盾样本准确率↑ |
| D12 工具分层 | 全 agent 用工具统一、推理各司其职 | 工具成功率 + 平均延迟↓ |

**总效果一句话**：简单的不再浪费钱和时间（快车道），复杂的不再简单敷衍（专家会诊+真辩论），多模态判断不再文本中心（证据化融合），人工审核真正接上（不再断线）。
