# 内容风控智能治理系统 — 项目介绍

> 本文档适合刚接触项目的人阅读。用通俗语言介绍：项目是做什么的、有哪些功能、用到了什么技术、为什么要这样选。

---

## 一、一句话介绍

这是一个运行在你电脑上的"AI 内容安全审核中台"。它能自动检测用户提交的文本、图片、音频、视频中是否包含违规内容（色情/暴力/政治/广告/辱骂/虚假信息等），背后由 **12 个 AI Agent** 通过 LangGraph 协同驱动。

全部代码约 30,000 行 Python + TypeScript，在单机上就能运行。

它要解决三个核心痛点：
1. **多模态违规内容人工审核效率低** — 图文音混排内容靠人工逐条看，成本高速度慢
2. **黑灰产对抗手法层出不穷** — 违规内容藏进大段正常文本、藏在图片里、用变体字绕过关键词
3. **大模型审核成本高** — 必须让便宜的本地规则和贵的大模型各司其职

## 二、核心功能

### 文本审核

用户提交一段文字，系统会：
1. **敏感词检测** — 基于 AC 自动机，毫秒级扫描敏感词库（支持热更新，运营改了立即生效）
2. **黑灰产识别** — 自动检测批量生成、关键词变体（"威信号"替代"微信"）、格式伪装等对抗手法
3. **对抗文本检测** — 识别同音字替换、拆字（"亻尔"→"你"）、Unicode 混淆、火星文
4. **RAG 案例检索** — 从历史审核案例库中检索相似案例，作为 AI 判定的参考
5. **核心记忆增强** — 召回以前的高风险案例（"这个账号之前发过 3 次诈骗内容"）
6. **AI 语义分析** — DeepSeek 大模型理解文本深层含义，给出违规类型和置信度
7. **AIGC 检测** — 判断文本是否由 AI 生成（统计学特征 + 语义特征 + 结构特征）
8. **综合评分** — 关键词密度 × 0.3 + 语义置信度 × 0.5 + 历史案例相似度 × 0.2

针对"违规藏进大量正常文本"这一对抗手法的 **双重防漏审机制**：
- **规则命中段注入（P3）** — 敏感词/黑灰产模式/对抗规则命中的片段，连同前后文一起单独拎出来注入 DeepSeek 的 prompt，明确要求"逐字核查这些片段，不要因为混在正常文本中就忽略"。即使违规只占整篇文本的 1%，也能被聚焦审查。
- **长文本分段审核（P3.5）** — 文本超过 3000 字时自动分段（段落边界优先切块），每块独立跑完整审核链路并**并行**执行，最后合并取保守风险分。避免超长文本让大模型"注意力稀释"导致漏审。

整个过程约 **1-2 秒**（短文本）；长文本按块数线性增加，但块间并行。

### 图片审核

用户上传一张图（或文档里嵌的图），系统会：
1. **VL 视觉分析** — Qwen3-VL 多模态大模型理解图像内容（有什么人/物/场景/文字）
2. **OCR 文字提取** — 提取图中的所有文字
3. **上下文感知** — 如果图片嵌在文档中，注入前后 500 字的文本作为上下文（"这张图配的文字是什么？图文一致吗？"）
4. **相似图匹配** — dHash 计算图片指纹，与违规图片库比对（汉明距离判断相似度）
5. **以图搜图** — CLIP 模型提取视觉特征（512 维），在向量库中检索视觉相似的历史违规图片
6. **文字分类** — OCR 文字送入文本审核管线（敏感词+语义+RAG）

针对图片环节的防漏审设计：
- **位置化融合（P2）** — 文档里每张嵌入图都有精确的字符位置（char_position）。VL 分析完图片后，图片描述**插回它原本在文档中的位置**，变成"上文-图片描述-下文"，保持原文上下文逻辑一致。同时每张图的违规判定（如"此图含色情广告"）也一起注入，让后续文本审核知道"这里有一张有问题的图"。
- **VL 失败降级** — 如果视觉模型不可用（欠费/超时），绝不静默放行。图片会被标记为"待人工复核"（风险分 0.55 中风险），进入 REVIEW 流程保证有人兜底，而不是当没看见。

### 音频审核

用户上传一段语音，系统会：
1. **语音转文本** — FunASR 高精度语音识别（支持中文、方言、带噪语音）
2. **说话人分离** — 3D-Speaker 识别不同说话人，标注每段话是谁说的
3. **情感检测** — 判断说话人情绪（生气/着急/正常）
4. **文本审核** — 转写文字送入完整的文本审核管线

整个过程约 **10-20 秒**（瓶颈在 ASR 转写）。

### 视频审核

用户上传一段视频，系统会：
1. **ffmpeg 抽帧** — 关键帧采样，最多 10 帧
2. **逐帧 VL 分析** — 每帧调用 Qwen3-VL 做视觉违规检测
3. **音频轨道提取** — ffmpeg 抽取音频 → FunASR 转写 → 文本审核
4. **时间轴风险对齐** — 将帧分析结果与音频文字结果按时序对齐，定位"第几秒出现了违规内容"
5. **综合评分** — 帧分析 0.7 + 音频文字 0.3

### 多模态审核

对于复杂内容（一个 DOCX 文档里包含文字和多张图，再加一段音频），系统启动 **Planner v4.0 多模态编排**，按五阶段固定路线执行：

```
Phase 1 文件解析    → FileAgent 拆解文档, 提取文字 + 嵌入图片(带精确字符位置)
Phase 2 并行模态分析 → 所有图片 ‖ 音频 同时分析 (Semaphore(5) 并发限流)
Phase 3 上下文融合   → OCR文字 + 视觉描述(按位置插回) + ASR转写 → 合并文本 → TextAgent
Phase 4 跨模态关联   → 规则引擎检测 图文矛盾/图文互证/OCR融合/音频关联 (0 LLM 调用)
Phase 5 结果输出     → 写入 state, 标记 Planner 已处理, 避免下游重复审核
```

关键设计：
- **固定路线编排而非 LLM 自主调度** — "有图调 ImageAgent、有音频调 AudioAgent"是确定性问题，不需要让大模型做调度决策。调度阶段**零推理开销**，大模型只负责推理（"这段文字违不违规？"）。
- **图片上下文感知** — 每张嵌入图都带有它在文档中的 ±500 字上下文，VL 分析时连同上下文一起理解（"图片是配这段文字的吗？图文一致还是矛盾？"）。
- **位置化融合（P2）** — Phase 3 融合时，图片描述按 char_position 精确插回原文档位置，保持"上文-图片描述-下文"的逻辑连贯，而不是把所有图片描述堆在文档末尾。
- **幂等防重复** — Phase 5 标记 `_planner_processed`，LangGraph 状态图严格传递声明字段，下游 FileAgent/TextAgent 检测到已处理就跳过，避免同一批图片被重复分析多轮（曾导致 21 张图被处理 61 次）。
- **性能实测** — 多模态混合文档（21 张图 + 长文本）通过并行编排 + 并发限流约 **2 分钟**完成；跨模态互证可使判定置信度提升 **15%**。

### 多 Agent 协同

对于复杂请求，12 个 AI Agent 像团队一样协作，但**不是每个请求都走全链路**——系统先通过 **分诊台三车道路由** 决定走哪条路：

```
用户提交内容
  → 分诊台 (Triage): 用 ModelRouter 估风险×复杂度
      ├── low 快车道  → 本地小模型 + 规则快速判定 (无大模型调用, 最省成本)
      ├── med 标准车道 → 完整多 Agent 审核链路 (LLM 深度分析)
      └── high 专家车道 → 大脑仲裁 (超复杂/超长/强信号堆叠, 人工兜底)
```

以 med 标准车道的多模态审核为例：

```
用户提交一个含图文和音频的文档
  → Supervisor: "这是 multi_modal，需要调度"
  → Planner: "我先解析文件 → 图片和音频并行分析 → OCR+ASR 融合 → 统一审核"
    → FileAgent: 拆解 DOCX，提取文字和 20 张嵌入图（带位置锚定）
    → ImageAgent × 21: 每张图 VL(带±500字上下文)+OCR+dHash（并行）
    → AudioAgent × 1: 语音转文字（并行）
    → TextAgent: 融合文本(图片描述按位置插回) → keyword+RAG+分段/命中段审查+DeepSeek
    → 跨模态关联: 图文互证→confidence 提升
  → Debate Panel: "文本判广告、图片判广告、音频判广告——一致！快速共识"
  → RiskAgent: 综合评分→REJECT
```

**质量保障四级机制**：多 Agent 意见不一致时触发**辩论面板**（快速共识/多数投票/加权投票/升级人工）；置信度不足时触发**自我反思**修正；复杂疑点走 **ReAct 深挖**；最终疑点交给**人工兜底**（LangGraph interrupt 暂停工作流等人工判定）。普通内容只走 3-4 个 Agent 快速通过，复杂内容才走完整链路深度分析。

### 自动标注

每条审核完成后，AnnotationAgent 自动对结果做"二审"：
1. **规则引擎复核** — 用 6 大类约 70 个关键词快速检查（纯本地，约 1 毫秒）
2. **快速跳过** — 如果规则引擎的判断和模型一致且明确→直接判正确，省去后续步骤
3. **LLM 独立审核** — 不一致时才调 DeepSeek，用不同的 prompt 和更高的 temperature 重新判断
4. **语义矛盾检测** — 检查"判为 porn 但理由写的是广告"这种自相矛盾
5. **三方投票** — 规则引擎 + LLM + 矛盾检测，2 票认为错→标记为错误案例

### 自动优化

标注 Agent 发现的错误案例积攒到 100 条时，OptimizationAgent 自动触发：
1. **LLM 分析错误模式** — "误判有 30 个，漏判有 15 个，类型错误有 8 个..."
2. **自主决策优化方向** — 改 Prompt、加关键词、调阈值、补 RAG 案例
3. **生成新版本** — 版本号从 1.0.0 升到 1.1.0，支持 A/B 验证和回滚

### 关键选型理由

> （以下用最简单的话解释"为什么不选别的"）

**为什么选 LangGraph 做 Agent 编排？**
- 支持"先路由再并行再串行"的复杂工作流（条件边 + 串行边 + 并行节点）
- 提供 MemorySaver checkpointer 做状态持久化（崩溃后可以恢复）
- interrupt() API 支持 Human-in-the-Loop 暂停工作流等人工判定
- 比自研状态机更标准化，比 LangChain AgentExecutor 更灵活

**为什么选 DeepSeek 做 LLM？**
- 性价比极高，比 OpenAI 便宜约 90%
- API 兼容 OpenAI 格式，迁移成本低
- 1M 上下文窗口，适合长文本审核

**为什么选 BGE-M3 做文本嵌入？**
- 免费开源，能本地部署（不用每次都调 API，省成本省时间）
- 中文效果优于 OpenAI text-embedding-ada-002
- 1024 维信息密度高

**为什么 Planner 用固定路线而非 LLM 自主规划？**
- 多模态调度问题有确定答案：有图→ImageAgent，有音频→AudioAgent
- 不需要让 LLM 回答"先调哪个 Agent"——这只会浪费 2-5 秒和 Token
- LLM 的价值在推理（"这段文字违不违规？"），不在调度（"我该调谁？"）

**为什么 Skill 和 MCP 分离？**
- Skill = 知识层（HOW）：告诉 Agent "遇到同音字替换应该先归一化再检测"
- MCP = 能力层（WHAT）：提供 keyword_check 等工具的执行能力
- 知识迭代不影响工具稳定性，工具升级不影响知识准确性
- 参考 Anthropic 的 Skill 系统和 MCP 协议设计理念

## 四、系统亮点

### 1. 12 Agent 协同——不只一个模型

系统有 12 个专门的 AI Agent 像团队一样协作。普通内容只走 3-4 个 Agent，快速通过；复杂内容走完整的 12 Agent 链路，深度分析。每个 Agent 只在需要时才被触发，不会浪费资源。

### 2. 自动进化——越用越准

内置自动标注 + 优化闭环。每一条审核都经过 AnnotationAgent 二审，发现的错误累积到 100 条后自动触发 OptimizationAgent 分析原因并改进 Prompt。就像有一个质检员和培训师在不停地优化系统。

### 3. 从不"死掉"——完善的降级策略

任何服务挂了系统都能继续运行：

| 服务 | 挂了怎么办 |
|------|-----------|
| PostgreSQL | 无降级（必须） |
| Redis | 用本地内存字典替代 |
| ChromaDB | 跳过向量检索（RAG 退化为纯规则） |
| DeepSeek API | 用规则模板替代（关键词+正则） |
| Qwen3-VL | Mock 模式（基于图片基础信息做启发式判断） |
| FunASR | 跳过 ASR（音频审核不可用） |
| NetworkX | 跳过图谱扩展（GraphRAG 不可用） |

### 4. 全链路追踪——每个请求都能追

每次审核从输入到返回，所有步骤都有日志记录：

```
审核: "加我微信赚钱" (耗时 1.5 秒)
  → Supervisor: 内容分类 (5ms)
  → TextAgent: 敏感词3个|违规=advertisement|conf=0.88 (1,200ms)
  → AgenticRAG: 检索12条|置信度0.78|3轮 (200ms)
  → Debate: 快速共识 (1ms)
  → RiskAgent: REJECT|score=0.82 (50ms)
```

日志在 `logs/` 目录，pipeline.jsonl 文件每行是一个请求的所有步骤。

### 5. 策略热更新——改了立即生效

前端策略管理界面修改敏感词库或调整阈值→通过 Redis 缓存读取→Agent 在下次调用时直接使用新配置。**不需要重启服务**。

### 6. 多模态跨模态理解——不是各看各的

文档中的图片不是孤立分析的。系统会提取图片周围的文字（±500 字）作为上下文，让 VL 模型判断"这张图是配这段文字的吗？图文一致还是矛盾？"。所有图片的 OCR 文字会合并到原始文本中统一审核，音频转写也会一起合并。而且图片描述会**按它在文档中的精确位置插回原文**（"上文-图片描述-下文"），保证上下文逻辑不被打乱。

### 7. 防漏审三重防线——违规藏得再深也揪出来

黑灰产最常见的对抗手法是把违规内容**藏进大段正常文本**或**藏在文档图片里**。系统用三层机制对抗：

| 防线 | 应对手法 | 机制 |
|------|---------|------|
| 规则命中段注入 | 违规混在长文本中 | 敏感词命中片段拎出来单独注入 prompt 逐字核查 |
| 长文本分段审核 | 超长文本稀释注意力 | >3000 字自动分段并行审核，每块独立判断 |
| VL 失败降级 | 视觉模型不可用就放行 | VL 挂了 → 图片标记"待人工复核"，绝不静默通过 |

### 8. 辩论与反思——AI 也可以"开会讨论"

当多个 Agent 意见不一致时（如 TextAgent 判"辱骂"但 ImageAgent 判"正常"），自动触发辩论面板。4 种模式：快速共识、多数投票、加权投票（考虑专业度×违规严重度）、升级人工。辩论后如果置信度仍低，触发 Reflexion 自我反思环节。

### 9. 三车道分流——低成本内容不花冤枉钱

分诊台先用本地规则估计"这条内容有多险、多复杂"，然后分流：**低风险**走快车道（本地小模型，零大模型调用）、**中等风险**走标准车道（完整审核）、**高风险**直接进大脑仲裁。让便宜的模型处理 80% 的普通内容，贵的模型只处理真正的难点，审核成本大幅下降。

### 10. 标注三方投票——不是简单对错

AnnotationAgent 不是简单地说"模型对/错"。它用三个独立视角交叉验证：关键词规则（本地，极快）、LLM 独立审核（不同的 prompt 和温度）、语义矛盾检测。2-of-3 投票，既有速度又有准确度。

## 五、项目规模

- **后端代码**：~29,500 行 Python
- **前端代码**：~7,000 行 TypeScript/TSX
- **Agent 数量**：12 个（Supervisor/Planner/File/Text/Image/Audio/Video/ReAct/Debate/Reflexion/Human/Risk）
- **MCP 工具**：8 个（keyword_check/history_search/image_hash/account_risk/adversarial_detect/url_check/content_dedup/regex_rule）
- **Skill 知识库**：3 个（keyword-check/history-search/image-hash）
- **RAG 类型**：5 种（Keyword/Agentic/MultiModal/CoreMemory/GraphRAG）
- **多模态编排**：Planner v4.0 固定路线五阶段（解析→并行模态→位置化融合→跨模态关联→输出）
- **车道路由**：三车道 low/med/high + 大脑仲裁 + 终止双签硬校验
- **防漏审机制**：规则命中段注入 + 长文本分段审核（>3000 字）+ VL 失败降级待复核
- **API 接口**：9 个路由模块、30+ 个接口
- **数据库**：PostgreSQL 4 张表、Redis 5 种 key 模式、ChromaDB 2 个集合、NetworkX 1 个图
- **AI 模型**：4 个（DeepSeek V4 + Qwen3-VL + FunASR + BGE-M3）
- **标注引擎**：3 视角交叉验证（规则+LLM+矛盾），2-of-3 投票
- **优化引擎**：4 种优化动作（prompt_update/keyword_update/threshold_adjust/rag_case_add）
